## Point lights: windowed light boost, unnormalised normals, the slot leak (2026-11-08)

Modlog-gaps item 117 (MODLOG "Point lights on scenery", "Not done"). Addresses are Steven's FFXiMain.dll.
- The two-area-light scenery mode is already built (MODLOG "Config tool 0017", Lighting::two).
- Windowed light boost: every SetLight goes through FUN_1000bf30 (old FUN_1000b370; refuses a POINT with Range or
  Att2 < 0 and a DIRECTIONAL with direction 0, error 0x8876086c). It calls FUN_1000be50 (old FUN_1000b290) on a
  copy: only while DAT_10456a7c (config 0034) != 0, and only when the diffuse r, g and b are all below 0.8
  (0x3f4ccccd), each is multiplied by FUN_10017100's factor of its channel and set to 1.0 where it reaches 1. The
  factors are 2.3 / 65535 (0x381333c6) x the gamma ramp (device +0x1f4 + 4) at red entry 120, green 116, blue 128.
  FUN_100171b0 builds each ramp, ftol(65535 (i x f32(1 / 255))^(1 / max(g + DAT_10456a9c, 0.01))), whether or not
  FUN_10017230 then sets it (full screen only). g per channel from FUN_101aa650: v x 0.01 - 0.5 + 1.5 = 1 + v / 100
  (Gameplay 0x37..0x39); with base 0028 as ours already takes it. At the defaults (g 1.5) the factors are 1.3915 /
  1.3604 / 1.4527 (test render::boost_tests). Ours: render::light_boost, set while 0034 != 0 (ZoneRenderer.light_boost,
  Uniforms.boost); zone.wgsl `boost` on the sun, the two lights, the area lights, the actor light, the floor lamp and
  the scenery point lights (rgb / 128, so a lamp with a channel at 0x67 or more is never boosted). Ours keeps its
  relative gamma in the scaling pass on top *(not retail: windowed retail has no ramp)*.
- Unnormalised normals: FUN_1017c9c0 (old FUN_10175ac0) sets D3DRS_NORMALIZENORMALS (0x8f) from placement +0xe per
  draw (FUN_1017b510 resets it to 0 per holder). The loader FUN_10179430 sets +0xe only when the zone is 0xd5, the name
  starts es_anmo (0x10377888) and the position is within 0.05 (0x3d4ccccd) of (-57.9466, -15.7264, -269.387)
  (0x1033677c / 78 / 74). Census (dat::zone::tests::light_ref_census): exactly one such placement, in zone 213.
  Everything else lights with D3D's normal through the inverse transpose of the world matrix, unnormalised: a
  placement scaled by s sees N.L / s, and the vertex normal's length counts (19.4M of 19.55M MMB normals are unit
  within 0.01, 131k shorter than 0.9). 345,123 of 880,108 drawn scenery placements have a scale other than 1.
  Ours: vs_main transforms the normal by the cofactors / det (the direction was model x n, wrong for unequal
  scales), and every N.L in lit_zone (sun, the two lights, the point lights) takes its length (VertexOut.nscale; 1
  with Placement::normalize, instance area.z).
- The bump vertex shader path ignores NORMALIZENORMALS: its sun vector is c4 = -(sun direction x inverse world) against
  the object-space N, T and B = N x T, so the same 1 / s. vs_main now builds oD1 that way, clamped as the colour
  register is. Its point lights (object space, I s^2 / d^2) belong to item 118.
- Seen: zone-shot 102 at 09:00 before / after, the scaled trees a little darker, no other change.
- Slot leak census (drawn scenery, zones 0..299 and 1000..1299): 172,656 light refs, 470 to 'c' keys (e.g. zone 14
  jillmachine c01 / c01a, zone 33 _water_id01_m cl01..), none to an empty list record or past the list. FUN_1017b510
  disables slots +0x394b0..+0x394bc and zeroes the caches +0x39100..+0x3910c at the start of each holder, then draws
  the camera list (or every placement whose +8 > 1) in order, deferring those with +0xf (file +0x46 bit 2) to a queue
  drawn after; FUN_1017c9c0 returns before the lights when the placement is past its distance, outside the frustum
  (FUN_10181bb0) or has no mesh at that distance. So a 'c' ref keeps the light of the last drawn placement before it
  whose ref in that slot is 0 (off) or a valid key, or off when there is none.
- Ours (render/leak.rs): a geometry with such refs keeps each placement's refs (Off / Set / Keep), its queue flag
  (Placement::deferred) and its instances with their culling bounds. Per frame (App before render, zone-shot too),
  ZoneRenderer::update_leak walks back from each leaker in that order (the camera list in force, else every
  placement) to the last placement drawn under cs_cull_vis's own test (distance, band, the seven planes; a hidden
  stand-in is not drawn) whose ref there is not Keep, and writes the leaker's instances' slots; where that leaves a
  slot off, the Lamp Lights patch keeps it. Test render::leak::tests::keep_takes_last_drawn. In the install only 8 of
  the 470 'c' refs follow a placement with a light in that slot in record order (zones 231, 237, 243, 245, 246), so
  nearly all resolve to off as before; zone-shot 14 / 33 / 243 / 231 / 237 views wrote off. Sub-areas (the second
  holder) are not replayed *(their MZBs were not in the census)*.
