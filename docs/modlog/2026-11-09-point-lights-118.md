## Point lights: the bump shaders' constants, the placement inverse, retail's per-vertex lights (2026-11-09)

Modlog-gaps item 118 (MODLOG "Point lights on scenery": c0..c3 and the order of the obj+0x80 inverse; the bump path's
point lights). Addresses are Steven's FFXiMain.dll.
- The shader text: line tables 0x10376ff8 / 0x10377048 / 0x103770d0 / 0x10377168 / 0x10377210 (vertex shaders for 0..4
  lights, 0x13 / 0x21 / 0x25 / 0x29 / 0x2d lines) and 0x103772c4 (ps.1.1, 9 lines), joined by FUN_10177090 and
  created by FUN_10178250 (zone +0x3946c.. = +0x39480.., +0x39494). Light k: `sub r0, c(11+k), v0`, `dp3 r1(.k), r0,
  r0`, `rsq r2(.k)`, `dp3 r3.k, r0, v3`; then `sge r5, c18, r1`, r3 x r2, r2 x r2, r3 x r2, max with c5 (0), x r5,
  `dp3` (`dp4` with 4 lights) r4.x / y / z with c15 / c16 / c17, x v5, `mad oT3, c7, v5, r4`. So oT3 = vc x (c7 +
  sum_k C_k max(N.(P_k - V), 0) / d^3 x (d^2 <= c18_k)), unclamped in the vertex shader; ps.1.1 `texcoord t3` clamps it
  per pixel. With one light `dp3 r1, r0, r0` fills every lane and r3.y / .z are never written; FUN_1017c9c0 zeroes
  c15..c17 (0x10639048.., all four lanes) before each draw, so unused lanes add 0.
- c0..c3 (FUN_1017c9c0, asm 0x1017d850..0x1017d8b1): D3DXMatrixMultiply(world +0x40, view-projection zone +0x38f5c)
  (0x102d6f29 by the fast table 0x103cc41c, x87 base at 0x103cc4f8 + 4 x 3), then D3DXMatrixTranspose (table index 37,
  base 0x102d7172), SetVertexShaderConstant(0, 4): the transposed world-view-projection, as `m4x4 r1, v0, c0` needs.
- c11..c14 = the light's Position (light +0x34) x placement +0x80 as a row vector (x' = x _11 + y _21 + z _31 + _41),
  in slot order over zone +0x3945c..+0x39468 (the slot leak's pointers), only those set; c15..c17 lane k = boosted
  (FUN_1000be50) Diffuse r / g / b x Theta (I); c18 lane k = Range^2. SetVertexShaderConstant(0xb, n), (0xf, 4).
- Placement +0x80 (FUN_10179430, asm 0x10179f28..0x1017a123): D3DXMatrixTranslation(-p), RotationZ(-z), RotationY(-y),
  RotationX(-x) (0x102d7a66 checked: _22 cos, _23 sin, _32 -sin, _33 cos), Scaling(1 / s, 1 when s is 0), multiplied
  in that order from the identity: T(-p) Rz Ry Rx S^-1, the exact inverse of the world S Rx Ry Rz T (ours,
  Placement::matrix). Census (dat::zone::tests::light_ref_census): 26 drawn placements have a zero scale (zone 41 / 126
  hit_turi, 249 kabe-atariyou, 55 com_id00), where retail's 1 stands in.
- On a voyage (FUN_1017c9c0 with its last argument set: world x V, 0x1017d819..) the inverse it uses for c4 (the sun)
  is D3DXMatrixTranspose(world x V): no 1 / s^2 and no translation. The point lights still take placement +0x80 (the
  placement's inverse, without V).
- Fixed function (FUN_10178530 / FUN_10178610): the table entry's Att0 / Att1 stay 0 (zero-filled), Att2 = 1 / I (1
  when I <= 0, Diffuse 0), so C I max(N.L, 0) / d^2 with the D3D range cut (none past Range), per vertex, the vertex
  colour then clamped.
- Ours: zone.wgsl vs_main computes the scenery's point lights per vertex (VertexOut.point): fixed function in world
  space with the normal as it comes (nscale), vc x the sum clamped; the bumped path in object space (inv_axis: row k
  = axis k / s_k^2, a zero scale the unit axis from the other two; the vertex's raw normal), vc x the sum unclamped
  and t3 clamped in fs_bump. A placement scaled by s now sees I s^2 / d^2 and range R s there. The bumped oD1 on a
  voyage uses the transpose. The old per-pixel lights with the floored distance and the (1 - (d/R)^4)^2 window are
  Settings' Light Shading Smooth (ours, config smooth_lights, default Retail; zone-shot FFXI_SMOOTH_LIGHTS=1).
